2) Externe URLs (Server Routing)

Ziel: Jeder Agent ist extern erreichbar über Pfad-Routing, z.B. opena3 unter https://hyperdashboard-one.de/opena3/. 

# Beispiel (extern)
https://hyperdashboard-one.de/opena1/
https://hyperdashboard-one.de/opena2/
https://hyperdashboard-one.de/opena3/
...
https://hyperdashboard-one.de/opena21/
https://hyperdashboard-one.de/browsep/
Nginx Template (Pfad-basiert /openaX/ → localhost:PORT, Prefix stripping) 
server {
  server_name hyperdashboard-one.de;

  # opena3 Beispiel: /opena3/ → 127.0.0.1:12347/
  location ^~ /opena3/ {
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;

    rewrite ^/opena3/(.*)$ /$1 break;
    proxy_pass http://127.0.0.1:12347;
  }

  # Dupliziere analog pro Agent:
  # opena1->12344, opena2->12345, opena4->12348, ...
}

5) Troubleshooting (die 3 Klassiker, die sonst Zeit klauen)

Start bricht sofort ab: “.env nicht gefunden”

Start bricht ab obwohl du “nur warnen” wolltest (set -e + grep)

Wenn OPENAI_API_KEY_OPENA1/2 in .env fehlen, kann grep Exit-Code 1 liefern und wegen set -e den Start killen. Fix in ops.sh: grep mit || true absichern und cut -d= -f2- nutzen.

monitor zeigt falsche Agent-Namen/Ports (bash -c Argumente)

Bei bash -c ist $0 das erste Argument nach dem Script-String. In ops.sh musst du im monitor-Block agent="$0"; folder="$1"; port="$2" verwenden (sonst shifted values).

Port-Policy: Wenn irgendwas 8080 nutzt, ist das ein Compliance-Fail. End of story.
