💚 Health & Models

Der /health-Endpoint liefert aggregierte Status-Informationen:

  • status – "ok" wenn Agent läuft
  • agent – Agent-Name (opena3)
  • port – Service-Port (12347)
  • uptime – Laufzeit in Sekunden
  • openwebui_available – Backend erreichbar?
  • models_count – Anzahl verfügbarer Modelle
GET /health Health-Check mit Status-Aggregation
GET /models/list Config-Modelle + Backend-Modelle
GET /v1/models OpenAI-kompatibler Alias

💬 Chat-Endpoints

opena3 leitet Chat-Requests an LocalAgent-Pro weiter, welches Ollama (llama3.1:8b) anspricht.

POST /chat Non-Streaming Chat (Dashboard → opena3 → LocalAgent-Pro)
POST /chat/stream SSE-Streaming (Events: start, chunk, end, error)
POST /v1/chat/completions OpenAI-kompatibler Alias
POST /command Command-Execution-Endpoint
POST /invoke Direct Tool Invocation

📦 Safepoints & Archiv

Jeder Chat-Request erzeugt CMD/RESP-Safepoints im Archiv:

  • Pfad: BASE_ROOT/1.opena1&2_portier/archivp_store
  • Format: SP<laufnummer>_src→dst_{CMD|RESP}.json
  • Index: index.jsonl (append-only)
  • Stream-Safepoints: RESP-Safepoint nach Stream-Ende mit Zusammenfassung

🔄 Option-2-Flow

Der Nachrichtenfluss im PORTIER-System:

  • Hinweg: OpenAI → opena1 → opena2 → opena3 (owuip)
  • Rückweg: opena3 → opena2 (Safepoint RESP)
  • Kein Bypass: Direktcalls zu opena3 sind verboten (nur via kordp)
