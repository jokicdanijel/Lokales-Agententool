opena3 – Developer Overview

Technische Dokumentation für Entwickler | PORTIER 3.0

🏗️ Architektur

  • FastAPI-App mit lifespan-Handler (kein @app.on_event mehr)
  • Pydantic V2 – alle Schemas mit model_config = ConfigDict(extra="forbid")
  • Sync HTTP-Client mit Retry + Exponential Backoff
  • Safepoints – Append-Only Archiv mit index.jsonl
  • SSE-Streaming – Server-Sent Events für /chat/stream

🔐 Security-Hinweise

Bearer-Token-Handling

  • ENV-Only: Bearer-Token ausschließlich via BEARER_TOKEN Umgebungsvariable setzen
  • Keine Hardcodes: Niemals Tokens in Code, Config-Dateien oder Git committen
  • .env-Datei: Muss in .gitignore stehen (bereits konfiguriert)
  • Token-Rotation: Regelmäßig neue UUIDs generieren (uuidgen oder python -c "import uuid; print(uuid.uuid4())")
# Beispiel .env (NICHT committen!)
BEARER_TOKEN=c899b90d-faf8-485b-afa4-078357cf5313
OPENA3_TIMEOUT=30
LOG_LEVEL=INFO

TLS/HTTPS-Empfehlungen

  • TLS-Offload: opena3 läuft intern auf HTTP – TLS wird durch vorgelagerten Reverse-Proxy terminiert
  • Empfohlene Proxies: nginx, Caddy, Traefik
  • Interne Kommunikation: Zwischen opena1 ↔ opena2 ↔ opena3 ist HTTP akzeptabel (localhost/intranet)
  • Externe Zugriffe: Immer über HTTPS (Port 443) via Reverse-Proxy
# Beispiel nginx-Config (Auszug)
server {
    listen 443 ssl;
    server_name api.example.com;
    
    ssl_certificate /etc/ssl/certs/api.pem;
    ssl_certificate_key /etc/ssl/private/api.key;
    
    location /opena3/ {
        proxy_pass http://127.0.0.1:12347/;
        proxy_set_header Authorization $http_authorization;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

Rate-Limiting & 429-Handling

Limit-TypWertKonfiguration
Global Requests/Minute60OPENA3_GLOBAL_RPM
Client Requests/Minute30OPENA3_CLIENT_RPM
Chat Requests/Minute20OPENA3_CHAT_RPM
Stream Requests/Minute10OPENA3_STREAM_RPM
  • Response bei Limit: HTTP 429 mit Retry-After Header
  • Client-Verhalten: Nach 429 → warten gemäß Retry-After, dann erneut versuchen
  • Deaktivieren (nur Dev): OPENA3_RATE_LIMIT_ENABLED=false

Secret-Masking in Logs

  • Automatisch maskiert: token, password, secret, key, bearer, auth
  • Log-Ausgabe: Authorization: Bearer ***
  • Safepoints: Secrets werden vor Archivierung entfernt/maskiert
# Beispiel: Maskierte Log-Ausgabe
2025-12-01 10:00:00 [INFO] Request headers: {"Authorization": "***", "Content-Type": "application/json"}

Port-Policy (PORTIER 3.0)

  • Erlaubter Bereich: 12344–12399
  • Verbotene Ports: 8080 (reserviert für OpenWebUI UI)
  • Enforcement: PortPolicy.is_valid_port() bei Startup
  • Verstoß: Service startet nicht bei ungültigem Port

Option-2-Flow (Sicherheitsarchitektur)

  • Kein Direktzugriff: OpenAI/externe Clients sprechen nie direkt mit opena3
  • Fluss: OpenAI → opena1 (kordp) → opena2 (archivp) → opena3 (owuip)
  • Safepoint-Audit: Jeder Request wird in archivp_store protokolliert
  • Manipulation erschwert: Append-Only Archiv, keine Löschung/Änderung
