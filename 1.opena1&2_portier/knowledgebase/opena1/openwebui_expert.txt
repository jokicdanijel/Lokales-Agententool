🤖 Beginnen mit OpenAI
Überblick​
Open WebUI erleichtert die Verbindung und Nutzung von OpenAI und anderen OpenAI-kompatiblen APIs. Diese Anleitung führt Sie durch das Hinzufügen Ihres API-Schlüssels, das Festlegen des richtigen Endpunkts und die Auswahl von Modellen – damit Sie sofort mit dem Chatten beginnen können.

Schritt 1: Holen Sie sich Ihren OpenAI-API-Schlüssel​
Um OpenAI-Modelle (wie GPT-4 oder o3-mini) zu verwenden, benötigen Sie einen API-Schlüssel von einem unterstützten Anbieter.

Sie können verwenden:

OpenAI direkt ( https://platform.openai.com/account/api-keys )
Azure OpenAI
Jeder OpenAI-kompatible Dienst (z. B. LocalAI, FastChat, Helicone, LiteLLM, OpenRouter usw.)
👉 Sobald Sie den Schlüssel haben, kopieren Sie ihn und halten Sie ihn griffbereit.

Für die meisten OpenAI-Anwendungen lautet die Standard-API-Basis-URL: https://api.openai.com/v1

Andere Anbieter verwenden andere URLs – prüfen Sie die Dokumentation Ihres Anbieters.

API-Schlüssel: Fügen Sie Ihren Schlüssel hier ein
Klicken Sie auf Speichern ✅.

Dadurch werden Ihre Anmeldeinformationen sicher gespeichert und die Verbindung hergestellt.

🌟 OpenAPI-Tool-Server
Dieses Repository bietet Referenzimplementierungen des OpenAPI Tool Servers, die Entwicklern die einfache und sichere Integration externer Tools und Datenquellen in LLM-Agenten und -Workflows ermöglichen. Diese Implementierungen sind auf maximale Benutzerfreundlichkeit und minimalen Lernaufwand ausgelegt und nutzen die weit verbreitete und praxiserprobte OpenAPI-Spezifikation als Standardprotokoll.

Durch die Nutzung von OpenAPI benötigen Sie kein proprietäres oder unbekanntes Kommunikationsprotokoll mehr. So können Sie schnell und sicher Server erstellen oder integrieren. So sparen Sie Zeit bei der Entwicklung benutzerdefinierter Schnittstellen und haben mehr Zeit für die Entwicklung leistungsstarker Tools zur Optimierung Ihrer KI-Anwendungen.

☝️ Warum OpenAPI?​
Etablierter Standard : OpenAPI ist ein weit verbreiteter, produktionserprobter API-Standard, der von Tausenden von Tools, Unternehmen und Communities unterstützt wird.

Das Rad muss nicht neu erfunden werden : Keine zusätzliche Dokumentation oder Verwirrung durch proprietäre Spezifikationen. Wenn Sie heute REST-APIs erstellen oder OpenAPI verwenden, sind Sie bereits startklar.

Einfache Integration und Hosting : Stellen Sie Ihre Tool-Server extern oder lokal bereit, ohne Anbieterbindung oder komplexe Konfigurationen.

Starker Sicherheitsfokus : OpenAPI basiert auf HTTP/REST-APIs und unterstützt von Natur aus weit verbreitete, sichere Kommunikationsmethoden, einschließlich HTTPS und bewährter Authentifizierungsstandards (OAuth, JWT, API-Schlüssel).

Zukunftssicher und stabil : Im Gegensatz zu weniger ausgereiften oder experimentellen Protokollen verspricht OpenAPI Zuverlässigkeit, Stabilität und langfristige Unterstützung durch die Community.

Offene WebUI-Integration
Überblick​
Open WebUI v0.6+ unterstützt die nahtlose Integration mit externen Tools über die OpenAPI-Server – das heißt, Sie können Ihre LLM-Workflows problemlos mithilfe von benutzerdefinierten oder Community-basierten Tool-Servern erweitern 🧰.

In dieser Anleitung erfahren Sie, wie Sie einen OpenAPI-kompatiblen Tool-Server starten und ihn über die intuitive Benutzeroberfläche mit Open WebUI verbinden. Los geht's! 🚀

Schritt 1: Starten Sie einen OpenAPI-Tool-Server​
Zunächst müssen Sie einen der im OpenAPI-Servers-Repository verfügbaren Referenz-Tool-Server starten . Für einen schnellen Test verwenden wir den Time-Tool-Server als Beispiel.

🛠️ Beispiel: Lokales Starten des timeServers

git clone https://github.com/open-webui/openapi-servers
cd openapi-servers

# Navigate to the time server
cd servers/time

# Install required dependencies
pip install -r requirements.txt

# Start the server
uvicorn main:app --host 0.0.0.0 --reload
￼
Nach der Ausführung wird ein lokaler OpenAPI-Server unter http://localhost:8000 gehostet , auf den Sie Open WebUI verweisen können.

￼

Schritt 2: Tool-Server in Open WebUI verbinden​
Verbinden Sie als Nächstes Ihren laufenden Tool-Server mit Open WebUI:

Öffnen Sie die WebUI in Ihrem Browser.
Öffnen Sie ⚙️  Einstellungen .
Klicken Sie auf ➕ Tools, um einen neuen Tool-Server hinzuzufügen.
Geben Sie die URL ein, unter der Ihr OpenAPI-Toolserver ausgeführt wird (z. B. http://localhost:8000 ).
Klicken Sie auf „Speichern“.
￼

🧑‍💻 Benutzer-Tool-Server vs. 🛠️ Globale Tool-Server​
Es gibt zwei Möglichkeiten, Tool-Server in Open WebUI zu registrieren:

1. Benutzertool-Server (über die regulären Einstellungen hinzugefügt)​
Nur für den Benutzer zugänglich, der den Tool-Server registriert hat.
Die Verbindung wird vom Benutzer direkt vom Browser (Client-Seite) hergestellt.
Perfekt für persönliche Arbeitsabläufe oder zum Testen benutzerdefinierter/lokaler Tools.
2. Globale Tool-Server (hinzugefügt über die Admin-Einstellungen)​
Administratoren können gemeinsam genutzte Toolserver verwalten, die allen oder ausgewählten Benutzern in der gesamten Bereitstellung zur Verfügung stehen:

Gehen Sie zu 🛠️ Admin-Einstellungen > Tools .
Fügen Sie die Tool-Server-URL genauso hinzu, wie Sie es in den Benutzereinstellungen tun würden.
Diese Tools werden ähnlich wie die integrierten Tools von Open WebUI behandelt.
Hauptunterschied: Woher kommen die Anfragen?​
Der Hauptunterschied zwischen User Tool Servern und Global Tool Servern besteht darin, wo die API-Verbindung und die Anfragen tatsächlich erfolgen:

Benutzer-Tool-Server

Anfragen an den Tool-Server werden direkt von Ihrem Browser (dem Client) ausgeführt .
Dies bedeutet, dass Sie sich sicher mit Localhost-URLs (wie http://localhost:8000) verbinden können – und dabei sogar private oder nur für die Entwicklung vorgesehene Endpunkte wie Ihr lokales Dateisystem oder Ihre Entwicklungstools offenlegen können – ohne das Risiko einzugehen, dass die Daten im weiteren Internet oder bei anderen Benutzern preisgegeben werden.
Ihre Verbindung ist isoliert; nur Ihr Browser kann auf diesen Tool-Server zugreifen.
Globale Tool-Server

Anfragen werden vom Open WebUI-Backend/Server gesendet (nicht von Ihrem Browser).
Das Backend muss in der Lage sein, die von Ihnen angegebene Tool-Server-URL zu erreichen – also localhostden lokalen Host des Backend-Servers, nicht den Ihres Computers.
Verwenden Sie dies, um Tools mit anderen Benutzern in der gesamten Bereitstellung zu teilen. Beachten Sie jedoch: Da das Backend die Anforderungen stellt, können Sie über diese Methode nicht auf Ihre persönlichen lokalen Ressourcen (wie Ihr eigenes Dateisystem) zugreifen.
Denken Sie an die Sicherheit! Geben Sie nur Remote-/globale Endpunkte frei, die sicher sind und für den Zugriff durch mehrere Benutzer vorgesehen sind.
Übersichtstabelle:

Tool-Servertyp	Anfrageursprung	Localhost verwenden?	Anwendungsfallbeispiel
Benutzer-Tool-Server	Browser des Benutzers (Client-seitig)	Ja (privat für Sie)	Persönliche Tools, lokale Entwicklung/Tests
Globaler Tool-Server	WebUI-Backend öffnen (serverseitig)	Nein (es sei denn, es läuft auf dem Backend selbst)	Team-/gemeinsame Tools, Unternehmensintegrationen
TIPP
Benutzer-Tool-Server eignen sich am besten für persönliche oder experimentelle Tools, insbesondere solche, die auf Ihrem eigenen Computer ausgeführt werden, während globale Tool-Server ideal für Produktions- oder gemeinsam genutzte Umgebungen sind, in denen jeder Zugriff auf dieselben Tools benötigt.

👉 Optional: Verwenden einer Konfigurationsdatei mit mcpo​
Wenn Sie mehrere Tools über mcpo mithilfe einer Konfigurationsdatei ausführen, beachten Sie Folgendes:

🧩 Jedes Werkzeug ist unter seinem eigenen einzigartigen Pfad montiert!

Wenn Sie beispielsweise Speicher- und Zeittools gleichzeitig über mcpo verwenden, sind diese jeweils über eine eigene Route verfügbar:

http://localhost:8000/time
http://localhost:8000/Speicher
Das heisst:

Wenn Sie ein Tool in Open WebUI verbinden, müssen Sie die vollständige Route zu diesem bestimmten Tool eingeben – geben Sie NICHT nur die Stamm-URL ( http://localhost:8000 ) ein.
Fügen Sie jedes Tool einzeln in den Open WebUI-Einstellungen mithilfe der jeweiligen Unterpfad-URLs hinzu.
￼

✅ Gut:

http://localhost:8000/Zeit http://localhost:8000/Speicher

🚫 Ungültig:

http://localhost:8000

Dadurch wird sichergestellt, dass Open WebUI jeden Tool-Server korrekt erkennt und mit ihm kommuniziert.

🛠️ Globale Tool-Server sehen anders aus – und sind standardmäßig ausgeblendet!​
Wenn Sie einen globalen Tool-Server verbunden haben (d. h. einen, der vom Administrator konfiguriert wurde), wird dieser nicht automatisch im Eingabebereich angezeigt, wie dies bei Benutzer-Tool-Servern der Fall ist.

Stattdessen:

Globale Tools sind standardmäßig ausgeblendet und müssen pro Benutzer explizit aktiviert werden.
Um sie zu aktivieren, müssen Sie im Nachrichteneingabebereich (unten links im Chatfenster) auf die Schaltfläche ➕ klicken und die spezifischen globalen Tools, die Sie verwenden möchten, manuell aktivieren.

￼

⚠️ Wichtige Hinweise für globale Tool-Server:

Sie werden erst im Popup-Fenster der Werkzeuganzeige angezeigt, wenn sie über das Menü ➕ aktiviert werden.
Jedes globale Tool muss einzeln aktiviert werden, um in Ihrem aktuellen Chat aktiv zu werden.
Nach dem Einschalten funktionieren sie auf die gleiche Weise wie Benutzertools.
Administratoren können den Zugriff auf globale Tools über rollenbasierte Berechtigungen steuern.
Dies ist ideal für Team-Setups oder gemeinsam genutzte Umgebungen, in denen häufig verwendete Tools (z. B. Dokumentsuche, Speicher oder Websuche) für mehrere Benutzer zentral zugänglich sein sollten.

Open WebUI bietet eine Webhook-Funktion, mit der Sie automatisch Benachrichtigungen erhalten, wenn sich neue Benutzer bei Ihrer Instanz anmelden. Dies geschieht durch die Angabe einer Webhook-URL an Open WebUI. Open WebUI sendet dann Benachrichtigungen an diese URL, wenn ein neues Benutzerkonto erstellt wird.

Konfigurieren von Webhooks in Open WebUI
Sie benötigen eine Webhook-URL von einem externen Dienst, der Webhooks unterstützt, z. B. einem Discord-Kanal oder einem Slack-Arbeitsbereich. Diese URL wird verwendet, um Benachrichtigungen von Open WebUI zu empfangen.

Um Webhooks in Open WebUI zu konfigurieren, haben Sie zwei Möglichkeiten:

Option 1: Konfigurieren über die Admin-Oberfläche
Melden Sie sich als Administrator bei Ihrer Open WebUI-Instanz an.
Navigieren Sie zu Admin Panel.
Klicken Sie auf die SettingsRegisterkarte oben.
Navigieren Sie von dort zum GeneralAbschnitt „Einstellungen“ im Admin-Bereich.
Suchen Sie das Webhook URLFeld und geben Sie die Webhook-URL ein.
Speichern Sie die Änderungen.
Option 2: Konfigurieren über Umgebungsvariablen
Alternativ können Sie die Webhook-URL durch Festlegen der WEBHOOK_URLUmgebungsvariable konfigurieren. Weitere Informationen zu Umgebungsvariablen in Open WebUI finden Sie unter Konfiguration von Umgebungsvariablen .

Schritt 3: Überprüfen Sie den Webhook
Um zu überprüfen, ob der Webhook korrekt funktioniert, erstellen Sie in Open WebUI ein neues Benutzerkonto. Wenn der Webhook korrekt konfiguriert ist, sollten Sie unter der angegebenen Webhook-URL eine Benachrichtigung erhalten.

Webhook-Nutzlastformat
Die von Open WebUI gesendete Webhook-Nutzlast liegt im Klartext vor und enthält eine einfache Benachrichtigung über das neue Benutzerkonto. Das Nutzlastformat lautet wie folgt:

New user signed up: <username>

Wenn sich beispielsweise ein Benutzer namens „Tim“ anmeldet, lautet die gesendete Nutzlast:

New user signed up: Tim

Stellen Sie sicher, dass die Webhook-URL korrekt und richtig formatiert ist.
Überprüfen Sie, ob der Webhook-Dienst aktiviert und richtig konfiguriert ist.
Überprüfen Sie die Open WebUI-Protokolle auf Fehler im Zusammenhang mit dem Webhook.
Stellen Sie sicher, dass die Verbindung nicht durch eine Firewall oder einen Proxy unterbrochen oder blockiert wurde.

🏺 Artefakte
Was sind Artefakte und wie verwende ich sie in Open WebUI?​
Artefakte in Open WebUI sind eine innovative Funktion, die von den Artefakten von Claude.AI inspiriert wurde. Sie ermöglichen die Interaktion mit wichtigen und eigenständigen Inhalten, die von einem LLM innerhalb eines Chats generiert werden. Sie ermöglichen es Ihnen, wesentliche Inhalte unabhängig von der Hauptkonversation anzuzeigen, zu ändern, zu erweitern oder darauf zu verweisen. Dies erleichtert die Arbeit mit komplexen Ergebnissen und stellt sicher, dass Sie wichtige Informationen später erneut aufrufen können.

Wann verwendet Open WebUI Artefakte?​
Open WebUI erstellt ein Artefakt, wenn der generierte Inhalt bestimmte, auf unsere Plattform zugeschnittene Kriterien erfüllt:

Renderbar : Um als Artefakt angezeigt zu werden, muss der Inhalt in einem Format vorliegen, das von Open WebUI für die Darstellung unterstützt wird. Dies umfasst:
Einseitige HTML-Websites
Skalierbare Vektorgrafiken (SVG)
Vollständige Webseiten, die HTML, Javascript und CSS in einem Artefakt enthalten. Beachten Sie, dass zum Generieren einer vollständigen Webseite HTML erforderlich ist.
ThreeJS-Visualisierungen und andere JavaScript-Visualisierungsbibliotheken wie D3.js.
Andere Inhaltstypen wie Dokumente (Markdown oder einfacher Text), Codeausschnitte und React-Komponenten werden von Open WebUI nicht als Artefakte gerendert.

Wie erstellt das Modell von Open WebUI Artefakte?​
Um Artefakte in Open WebUI verwenden zu können, muss ein Modell Inhalte bereitstellen, die den Rendering-Prozess zur Erstellung eines Artefakts auslösen. Dazu muss gültiger HTML-, SVG-Code oder andere unterstützte Formate für das Artefakt-Rendering generiert werden. Wenn der generierte Inhalt die oben genannten Kriterien erfüllt, wird er in Open WebUI als interaktives Artefakt angezeigt.

Wie verwende ich Artefakte in Open WebUI?​
Wenn Open WebUI ein Artefakt erstellt, wird der Inhalt in einem speziellen Artefakt-Fenster rechts neben dem Hauptchat angezeigt. So interagieren Sie mit Artefakten:

Bearbeiten und Iterieren : Bitten Sie einen LLM im Chat, den Inhalt zu bearbeiten oder zu iterieren. Diese Aktualisierungen werden direkt im Artefaktfenster angezeigt. Sie können mit der Versionsauswahl unten links im Artefakt zwischen den Versionen wechseln. Jede Bearbeitung erstellt eine neue Version, sodass Sie Änderungen mit der Versionsauswahl verfolgen können.
Aktualisierungen : Open WebUI kann ein vorhandenes Artefakt basierend auf Ihren Nachrichten aktualisieren. Das Artefaktfenster zeigt den neuesten Inhalt an.
Aktionen : Greifen Sie auf zusätzliche Aktionen für das Artefakt zu, z. B. das Kopieren des Inhalts oder das Öffnen des Artefakts im Vollbildmodus. Diese Funktion befindet sich in der unteren rechten Ecke des Artefakts.
Artefakte bearbeiten​
Gezielte Updates : Beschreiben Sie, was Sie wo ändern möchten. Zum Beispiel:
„Ändern Sie die Farbe des Balkens im Diagramm von Blau auf Rot.“
„Aktualisieren Sie den Titel des SVG-Bildes auf ‚Neuer Titel‘.“
Vollständige Neufassungen : Fordern Sie größere Änderungen an, die den Großteil des Inhalts betreffen, um eine umfassende Umstrukturierung oder Aktualisierung mehrerer Abschnitte zu ermöglichen. Zum Beispiel:
„Schreiben Sie diese einseitige HTML-Website so um, dass sie stattdessen eine Zielseite wird.“
„Gestalten Sie dieses SVG neu, sodass es mit ThreeJS animiert wird.“
Bewährte Vorgehensweisen :

Geben Sie genau an, welchen Teil des Artefakts Sie ändern möchten.
Verweisen Sie für gezielte Aktualisierungen auf einen eindeutigen Identifizierungstext rund um Ihre gewünschte Änderung.
Überlegen Sie, ob für Ihre Anforderungen eine kleine Aktualisierung oder eine vollständige Neufassung besser geeignet ist.

Überblick​
Open WebUI ermöglicht die clientseitige Ausführung von Python-Code im Browser. Pyodide nutzt dabei Skripte innerhalb eines Codeblocks im Chat. Diese Funktion ermöglicht es Large Language Models (LLMs), Python-Skripte zu generieren, die direkt im Browser ausgeführt werden können. Dabei werden verschiedene von Pyodide unterstützte Bibliotheken genutzt.

Um die Privatsphäre und Flexibilität der Benutzer zu wahren, spiegelt Open WebUI PyPI-Pakete und vermeidet direkte externe Netzwerkanfragen. Dieser Ansatz ermöglicht auch die Nutzung von Pyodide in Umgebungen ohne Internetzugang.

Das Open WebUI-Frontend enthält eine eigenständige WASM (WebAssembly)-Python-Umgebung, die von Pyodide unterstützt wird und grundlegende, von LLMs generierte Python-Skripte ausführen kann. Diese Umgebung ist benutzerfreundlich gestaltet und erfordert keine zusätzliche Einrichtung oder Installation.

Eingabeaufforderungen
Der PromptsAbschnitt Workspaceinnerhalb der Open WebUI ermöglicht es Benutzern, benutzerdefinierte Eingabeaufforderungen zu erstellen, zu verwalten und freizugeben. Diese Funktion optimiert die Interaktion mit KI-Modellen, indem Benutzer häufig verwendete Eingabeaufforderungen speichern und über Schrägstrichbefehle einfach darauf zugreifen können.

Schnelles Management​
Die Eingabeaufforderungsoberfläche bietet mehrere wichtige Funktionen zum Verwalten Ihrer benutzerdefinierten Eingabeaufforderungen:

Erstellen : Entwerfen Sie neue Eingabeaufforderungen mit anpassbaren Titeln, Zugriffsebenen und Inhalten.
Teilen : Geben Sie Eingabeaufforderungen basierend auf konfigurierten Zugriffsberechtigungen an andere Benutzer weiter.
Zugriffskontrolle : Legen Sie Sichtbarkeits- und Nutzungsberechtigungen für jede Eingabeaufforderung fest ( weitere Einzelheiten finden Sie unter „Berechtigungen“ ).
Schrägstrichbefehle : Greifen Sie während Chatsitzungen mithilfe benutzerdefinierter Schrägstrichbefehle schnell auf Eingabeaufforderungen zu.
Erstellen und Bearbeiten von Eingabeaufforderungen​
Beim Erstellen oder Bearbeiten einer Eingabeaufforderung können Sie die folgenden Einstellungen konfigurieren:

Titel : Geben Sie Ihrer Eingabeaufforderung einen beschreibenden Namen zur einfachen Identifizierung.
Zugriff : Legen Sie die Zugriffsebene fest, um zu steuern, wer die Eingabeaufforderung anzeigen und verwenden kann.
Befehl : Definieren Sie einen Schrägstrichbefehl, der die Eingabeaufforderung auslöst (z. B. /summarize).
Eingabeaufforderungsinhalt : Schreiben Sie den eigentlichen Eingabeaufforderungstext, der an das Modell gesendet wird.
Eingabeaufforderungsvariablen​
Open WebUI unterstützt zwei Arten von Variablen, um Ihre Eingabeaufforderungen dynamischer und leistungsfähiger zu gestalten: Systemvariablen und benutzerdefinierte Eingabevariablen .

Systemvariablen werden bei Verwendung der Eingabeaufforderung automatisch durch den entsprechenden Wert ersetzt. Sie sind nützlich, um dynamische Informationen wie das aktuelle Datum oder Benutzerdetails einzufügen.

Benutzerdefinierte Eingabevariablen verwandeln Ihre Eingabeaufforderungen in interaktive Vorlagen. Wenn Sie eine Eingabeaufforderung mit diesen Variablen verwenden, wird automatisch ein modales Fenster angezeigt, in das Sie Ihre Werte eingeben können. Dies ist äußerst hilfreich für die Erstellung komplexer, wiederverwendbarer Eingabeaufforderungen, die wie Formulare funktionieren. Eine ausführliche Erklärung finden Sie in den folgenden Richtlinien.

Durch die Nutzung benutzerdefinierter Eingabevariablen können Sie statischen Text hinter sich lassen und interaktive Tools direkt in der Chat-Oberfläche erstellen. Diese Funktion ist kinderleicht konzipiert und ermöglicht selbst technisch nicht versierten Benutzern die einfache Ausführung komplexer, mehrstufiger Eingabeaufforderungen. Anstatt einen großen Textblock manuell zu bearbeiten, wird den Benutzern ein übersichtliches, strukturiertes Formular angezeigt. Dies optimiert nicht nur den Workflow, sondern reduziert auch Fehler, indem der Benutzer angeleitet wird, genau die richtigen Informationen im richtigen Format einzugeben. Es eröffnet eine neue Ebene der interaktiven Eingabeaufforderungsgestaltung und macht die Nutzung anspruchsvoller KI für jedermann zugänglich.
