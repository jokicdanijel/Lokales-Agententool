### ASSISTANT
Es sieht so aus, dass beim Starten des Website-Containers der Host-Port 3001 bereits belegt ist. Dadurch kann der Container den Mapping 0.0.0.0:3001 auf Port 80 im Container nicht binden, was zu den oben gezeigten Fehlern führt. Danach gab es weitere Fehler (ContainerConfig) – diese können von Versionskonflikten zwischen docker-compose und Docker stammen oder von einer Inkonsistenz der Compose-Datei. Hier ist ein Schritt-für-Schritt-Vorschlag, um Open WebUI sauber zum Laufen zu bringen:

- Prüfe, welcher Prozess Port 3001 belegt
  - sudo lsof -i -P -n | grep LISTEN | grep 3001
  - oder sudo ss -tulpn | grep 3001
  - Wenn ein Prozess gefunden wird, beende ihn (z. B. sudo kill <PID>), oder ändere den Port im Docker-Setup.

- Falls Port 3001 frei ist oder du ihn ändern willst
  - Öffne die docker-compose-Datei im Ordner docker-site and prüfe die Port-Mapping-Zeile, typischerweise something like:
    - ports: ["3001:80"]
  - Entweder halte ihn frei oder ändere ihn z.B. zu 3002:80 (ports: ["3002:80"]) und starte dann neu:
    - docker-compose down
    - docker-compose up -d

- Sorge für eine saubere Ausgangslage
  - docker-compose down -v
  - Optional: docker system prune -a -f (nur wenn du sicher bist, dass du ungenutzte Images/Volumes entfernen willst)
  - Danach wieder hochfahren:
    - docker-compose up -d

- Vermeide Verwechslungen mit mehreren Compose-Dateien
  - Stelle sicher, du arbeitest nur mit einer gültigen docker-compose.yml/.yaml im Ordner docker-site. Falls du versehentlich zwei Dateien hast, führe explizit -f docker-compose.yml oder -f docker-compose.yaml mit docker-compose up aus:
    - docker-compose -f docker-compose.yml up -d

- Prüfe Versionen und Kompatibilität (falls der Container immer noch Probleme macht)
  - docker --version
  - docker-compose --version
  - Falls nötig, aktualisiere Docker/Docker-Compose auf aktuelle stabile Versionen, da alte Versionen häufiger zu ContainerConfig-Fehlern führen können.

- Nach dem Start: Open WebUI erreichbar testen
  - Öffne im Browser die UI-URL deines Hosts auf dem verwendeten Port, z. B. http://localhost:3001 oder http://deine-maschine:3002, je nachdem, welchen Port du konfiguriert hast. Achte darauf, dass die URL vom Browser aus erreichbar ist und ggf. Firewalls/HTTPS bei Remote-Betrieb korrekt konfiguriert sind. Wenn die Verbindung nicht klappt, überprüfe die Logs:
    - docker-compose logs website (oder docker logs <container-id>)

- Wenn weiterhin Fehler auftreten (insbesondere ContainerConfig-Fehler)
  - Stell sicher, dass du eine kompatible docker-compose-Version verwendest und dein Docker-Engine aktuell ist.
  - Versuche eine Neuaufsetzung der Container nach Bereinigung der Umgebung.

Hinweis aus Open WebUI Dokumentation zur Fehlerbehebung bei Verbindungsproblemen: Stelle sicher, dass die URL korrekt ist und über den Browser zugänglich ist; prüfe bei Remote-Servern Firewalls und HTTPS-Konfigurationen; Open WebUI sollte idealerweise per Docker oder Systemdienst dauerhaft bereitgestellt werden [3].

Schritt 6 – Monitoring & Logs

Ziel: Sichtbarkeit der laufenden OpenWebUI-Umgebung sicherstellen, Logs prüfen und bei Problemen schnell reagieren.

Befehle:
```bash
# 1) Letzte 200 Zeilen der Website-Logs ansehen
docker compose logs --tail=200 website

# 2) Aktuellen Status der Container prüfen
docker compose ps

# 3) Health-Status des Website-Containers anzeigen (falls Healthcheck konfiguriert)
docker inspect --format='{{.State.Health.Status}}' docker-site-website-1 2>/dev/null || true

# 4) Netzwerk-Verbindungen zur UI prüfen (Port 8081)
ss -ltnp | grep -E '8081|80' || true

# 5) Firewallstatus prüfen (falls UFW aktiv)
sudo ufw status | grep -i 8081 || true
```

Erwarteter Output/Check:
- Logs zeigen aktuelle Aktivitäten und mögliche Fehlerquellen.
- Der Container-Status ist „Up“ und der Health-Status, falls vorhanden, sollte healthy sein.
- Port-Bindings (8081/80) sind aktiv und erreichbar.
- Firewall-Regeln erlauben Traffic auf 8081, falls UFW genutzt wird.

Fehlerhilfe (kurz):
- Logs zeigen Fehler im Backend oder Netzwerk; z. B. Verbindungsabbrüche -> prüfe Backend-Dienste/DB-Verbindungen in den Logs.
- Healthcheck fehlt oder läuft fehlschlagen -> überprüfe die Health-Endpoint-Konfiguration oder entferne ggf. Healthcheck-Abschnitt temporär.
- Firewall blockiert Port -> passe die Regeln an (z. B. ufw allow 8081/tcp).

Ziel: Healthcheck in der docker-compose.yaml hinzufügen (falls nicht vorhanden) und eine zuverlässige Neustart-Policy sicherstellen, damit der Service bei Problemen automatisch reagiert.

Befehle:
1) Sichern der bestehenden docker-compose.yaml
```bash
cp docker-compose.yaml docker-compose.yaml.bak
```

2) Docker-Compose-Datei manuell bearbeiten (Hinweis):
- Füge unter dem Website-Service folgende Einträge hinzu:
  - restart: unless-stopped
  - healthcheck:
      test: ["CMD-SHELL", "curl -f http://localhost:8081/ || exit 1"]
      interval: 30s
      timeout: 5s
      retries: 3
- Stelle sicher, dass die Einrückung korrekt ist ( YAML-Format).

3) Änderungen anwenden:
```bash
docker compose down
docker compose up -d
```

4) Kurzer Status-Check:
```bash
docker compose ps
ss -ltnp | grep 8081 || true
```

Erwarteter Output/Check:
- Website-Service läuft Up und bindet 8081 -> 80.
- Healthcheck wird ggf. beim nächsten Status-Check angezeigt (falls unterstützt) und sollte „healthy“ melden, sofern der Endpunkt erreichbar ist.

Fehlerhilfe (kurz):
- Healthcheck schlägt fehl: prüfe, ob der Endpunkt http://localhost:8081/ aus dem Container heraus erreichbar ist (z. B. curl im Container testen) und passe ggf. die URL oder den Endpunkt an.
- Neustart klappt nicht: prüfe Logs mit docker compose logs website und stelle sicher, dass kein Ressourcenlimit das Booten verhindert.
