# Portier-OpenAI Enterprise System Documentation

- **Schema Validation**: Strict JSON Schema Draft 2020-12 compliance
- **Signal Handling**: Graceful shutdown with SIGINT/SIGTERM support

7) Workflows

7.1 CLI‑Workflow (empfohlen für Automatisierung)

7.1 nach Schema erstellen (schemas/7.1-request.json).
opena1_client(_fixed).py ausführen → 7.2 erzeugen.
(Optional) src/opena1_archivator_client.py nutzen, um Archivator‑Forward/Health‑Check einzubinden.
python src/opena1_archivator_client.py --help  # falls CLI verfügbar
Der Archivator erzeugt beim Fluss opena1 → opena2 → kordp die Safepoints und aktualisiert index.jsonl.
7.2 Service‑Workflow (HTTP‑Endpoints)

Wenn dein Startskript (bootstrap_starter_fixed.py) die Services als HTTP‑Server startet, gelten folgende Labels/Endpoints:

POST /log/opena1 – Vor‑Safepoint (CMD)
POST /dispatch/kordp – Dispatch an Tool
POST /store/archivp – Snapshot (10er/Timeout)
POST /finalize/opena2 – Nach‑Safepoint (RESP)
curl‑Beispiele (ersetze $PORT durch einen freien Port 12344–12349):

# /log/opena1
curl -sS http://127.0.0.1:$PORT/log/opena1 \
  -H 'Content-Type: application/json' \
  -d '{"action":"move","cmd":{"example":"payload"},"resp":{"ok":true},"dst":"kordp"}'

# /dispatch/kordp
curl -sS http://127.0.0.1:$PORT/dispatch/kordp \
  -H 'Content-Type: application/json' \
  -d '{"src":"opena1","dst":"kordp","action":"dispatch","cmd":{"route":"A→B"},"resp":{"ok":true}}'

# /store/archivp
curl -sS http://127.0.0.1:$PORT/store/archivp \
  -H 'Content-Type: application/json' \
  -d '{"reason":"ten","count":10}'

# /finalize/opena2
curl -sS http://127.0.0.1:$PORT/finalize/opena2 \
  -H 'Content-Type: application/json' \
  -d '{"savepoint":"SP1_opena1→kordp","note":"fertig"}'
Wichtig: Services müssen via bootstrap_starter_fixed.py (oder Äquivalent) mit Port-Autowahl 12344–12349 gestartet werden. 8080 ist nicht erlaubt.

🔌 Modul: src/opena1_archivator_client.py (Produktion)

Der Portier‑OpenAI Archivator‑Client verbindet den Koordinator opena1 mit dem Archivator opena2. Er setzt strikt die Portier‑Regeln um (Ports 12344–12349, 8080 verboten) und erzeugt 7.2‑Antworten inkl. Archivator‑Infos.

Kernfunktionen

create_cmd_envelope_for_archivator(req, target_tool) Erstellt den 8.1‑CMD‑Envelope inkl. routing.via = ["opena1","opena2",target] und fester Env‑Blöcke.
create_archivator_request(req, cmd_envelope) Baut den 8.1‑Archivator‑Request (command="LOG_CMD_ENVELOPE", payload.log_type="CMD").
send_to_archivator(archivator_request) (async) POST auf http://127.0.0.1:12344/log/opena1, prüft strict==true und source=="opena2".
create_user_response_with_archivator_info(req, archivator_resp, selected_tool) Liefert 7.2 mit decision.archival_info (Status, Archivpfad, Safepoint‑Flag).
process_user_request_with_archivation(user_request) (async, End‑to‑End) Auswahl des Ziel‑Tools → CMD‑Envelope → Archivator → 7.2‑Antwort.
get_archivator_status() Health‑Check gegen /health.
Nutzung (Beispiel)

from src.opena1_archivator_client import OpenaOneArchivatorClient
client = OpenaOneArchivatorClient("http://127.0.0.1:12344")

status = client.get_archivator_status()
print(status)

Anforderungen

Python 3.13, venv venv313
Paket: requests (wird intern optional importiert; für Netzwerkaufruf erforderlich)
Kontrakte (wichtig)

7.1 Request: enthält mind. request_id, command, payload, routing.resolved_path
8.1 Archivator‑Request: command="LOG_CMD_ENVELOPE", payload.log_type="CMD", strict=true
8.2 Archivator‑Response: source="opena2", strict=true, decision.archival_status, decision.archive_path
7.2 User‑Response: decision.selected_tool, decision.archival_info, next="DISPATCHED_VIA_ARCHIVATOR"
