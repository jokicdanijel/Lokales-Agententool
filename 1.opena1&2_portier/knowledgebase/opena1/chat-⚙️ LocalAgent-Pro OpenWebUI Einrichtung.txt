Wichtige Port-/URL-Hinweise
- Dein LocalAgent-Pro API-Server läuft laut deinen Logs auf Port 8001 (Pfad: /v1/...).
- OpenWebUI sollte diese API verwenden:
  - API-Basis-URL in OpenWebUI: http://127.0.0.1:8001/v1
  - Endpunkt für Chat-Kompletions: http://127.0.0.1:8001/v1/chat/completions
  - Modellliste: http://127.0.0.1:8001/v1/models
- Dein Config-Eintrag „OpenWebUI Port“ mit 3000 ist unabhängig von der API-URL. Falls du OpenWebUI direkt zugänglich machen willst, halte Port 8001 für die API und verwende 8001 auch in der OpenWebUI-Verbindung, um Verwechslungen zu vermeiden.
- Um Überschneidungen zu vermeiden, empfiehlt sich:
  - OpenWebUI-API-Pfad und Server-Port konsistent halten (z. B. 8001) und den OpenWebUI-Port entsprechend anpassen, falls nötig.

Prüf- und Startbefehlsschritte (schnell getestet)
- Server-Start prüfen:
  - cd LocalAgent-Pro/src
  - python simple_agent.py
  - In der Konsole sollte am Anfang stehen, dass der Server läuft und OpenWebUI URL: http://127.0.0.1:8001/v1 erscheint.
- Grundlegende Gesundheit testen:
  - curl -s http://127.0.0.1:8001/health
  - Erwartet: JSON mit status ok, Modell, sandbox etc.
- Modelle-Auflistung testen:
  - curl -s http://127.0.0.1:8001/v1/models
  - Erwartet: JSON-Liste mit mindestens "localagent-pro" und dem LLm-Modell.
- Chat-Endpunkt testen:
  - curl -s -X POST -H "Content-Type: application/json" -d '{"messages":[{"role":"user","content":"Hallo LocalAgent-Pro"}]}' http://127.0.0.1:8001/v1/chat/completions
  - Erwartet: Eine OpenAI-kompatible Antwortstruktur mit Ihrem Agent-Text.

Fertiger Prompt/Text zum Copiloten (VSCode)
- Zweck: Den Copiloten exakt anweisen, wo OpenWebUI läuft, wie er starten soll und wie er die Verbindung prüfen soll.

Text für den Copiloten (Copy-Paste):
- Hinweis: OpenWebUI-Integration klären
  - Der LocalAgent-Pro-Server läuft auf Port 8001. Die OpenWebUI soll sich mit der API unter http://127.0.0.1:8001/v1 verbinden.
  - Setze in der OpenWebUI-Konfiguration als API-Basis-URL genau http://127.0.0.1:8001/v1.
  - Die OpenWebUI-Endpunkte befinden sich auf demselben Host:
    - OpenAI-kompatibler Endpunkt: http://127.0.0.1:8001/v1/chat/completions
    - Modell-Liste: http://127.0.0.1:8001/v1/models
  - Falls OpenWebUI versucht, auf Port 3000 zuzugreifen, korrigiere bitte die API-Basis-URL auf Port 8001 (und notiere dies in der Dokumentation).

- Schnelle Schritte für den Copiloten:
  1) Prüfe, ob der LocalAgent-Pro-Server wirklich auf 8001 läuft:
     - curl -s http://127.0.0.1:8001/health
  2) Prüfe die Modelle:
     - curl -s http://127.0.0.1:8001/v1/models
  3) Prüfe den Chat-Endpunkt:
     - curl -s -X POST -H "Content-Type: application/json" -d '{"messages":[{"role":"user","content":"Hallo LocalAgent-Pro"}]}' http://127.0.0.1:8001/v1/chat/completions
  4) In OpenWebUI die API-Basis-URL setzen:
     - API Basis-URL: http://127.0.0.1:8001/v1
  5) Starte OpenWebUI neu, teste eine einfache Abfrage, z. B. „Liste Dateien im Workspace“.
  6) Wenn Probleme auftreten, prüfe:
     - Server-Log-Ausgaben beim Start
     - Ob PORT 8001 blockiert oder von einer Firewall blockiert wird
     - Ob die JSON-Antworten dem OpenAI-Format entsprechen (id, object, choices, data)

  @app.route("/v1", methods=["GET"])

#!/usr/bin/env bash
set -euo pipefail

health=$(curl -sS "$BASE/health" || true)
if [ -z "$health" ]; then
  echo "Fehler: Health-Endpoint antwortet nicht."
  exit 1
fi
if echo "$health" | python3 -m json.tool >/dev/null 2>&1; then
  echo "Health-Response (JSON):"
  echo "$health" | python3 -m json.tool
  status=$(echo "$health" | python3 -c "import sys, json; d=json.load(sys.stdin); print(d.get('status',''))")
  if [ "$status" != "ok" ]; then
    echo "Warnung: Health-Status != ok (ist $status)"
    exit 2
  fi
else
  echo "Fehler: Health liefert kein gültiges JSON."
  echo "$health"
  exit 1
fi
echo

# Modelle prüfen
echo "2) Modelle (v1/models)"
models=$(curl -sS "$BASE/models" || true)
if echo "$models" | python3 -m json.tool >/dev/null 2>&1; then
  echo "Models-Response (JSON):"
  echo "$models" | python3 -m json.tool
else
  echo "Fehler: Models-Endpoint liefert kein gültiges JSON."
  exit 1
fi
echo

# Chat-Endpunkt testen
