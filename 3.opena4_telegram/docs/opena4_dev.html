📱 opena4 – Developer Overview

Technische Dokumentation für Telegram Gateway Agent | PORTIER 3.0

🏗️ Architektur

3.opena4_telegram/
├── main_telegram_agent.py    # FastAPI Entry Point (Port 12346) ✅
├── config.py                 # Pydantic V2 Config ✅
├── schemas.py                # Pydantic V2 Request/Response Schemas ✅
├── tests/                    # Pytest-Suite
│   ├── test_config.py        # Config + Whitelist Tests ✅
│   └── test_health.py        # Health Endpoint Tests ✅
├── bin/
│   ├── start_opena4.sh       # PID-basiertes Start-Skript ✅
│   └── stop_opena4.sh        # Stop-Skript ✅
├── docs/                     # HTML-Dokumentation ✅
├── logs/                     # Nohup-Logs
└── archivp/                  # Lokaler Safepoint-Speicher

Hauptkomponenten

  • FastAPI-Service auf Port 12346 – uvicorn mit CLI-Args
  • Telegram Bot: python-telegram-bot Library
  • Polling/Webhook: Konfigurierbar via --telegram-polling (mit Background-Thread)
  • Auth: Bearer Token Middleware + Telegram User Whitelist
  • Safepoints: Automatische Archivierung aller CMD/RESP mit Secret-Masking
  • datetime: Alle Timestamps mit datetime.now(timezone.utc) (UTC-aware)

⚙️ Konfiguration (ENV-Variablen)

# Telegram (PFLICHT)
TELEGRAM_BOT_TOKEN=123456789:ABC...xyz   # Bot-Token von @BotFather
TELEGRAM_ALLOWED_USER_IDS=7664467819     # Komma-separierte IDs

# PORTIER Integration
OPENA1_URL=http://127.0.0.1:12344        # kordp (Koordinator)
OPENA2_URL=http://127.0.0.1:12345        # archivp (Archivator)
BEARER_TOKEN=<uuid>                      # Bearer Auth für /command

# Optional
LOG_LEVEL=INFO                           # DEBUG, INFO, WARNING, ERROR
ARCHIVP_ROOT=../1.opena1&2_portier/archivp_store

🔄 Kommunikationsfluss

┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Telegram   │ ──► │   opena4    │ ──► │   opena1    │ ──► │  Tool/Agent │
│    User     │     │   (tgap)    │     │   (kordp)   │     │             │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
      ▲                    │                    │                    │
      │                    │                    │                    │
      └────────────────────┴────────────────────┴────────────────────┘
                           Antwort zurück via Option-2-Flow

Fluss-Details

  • 1. Telegram → opena4: User sendet Nachricht oder Command
  • 2. Whitelist-Check: Prüfe user_id gegen TELEGRAM_ALLOWED_USER_IDS
  • 3. CMD Safepoint: Request wird archiviert (src=opena4, dst=kordp)
  • 4. Forward to kordp: HTTP POST an opena1/opena2
  • 5. RESP Safepoint: Antwort wird archiviert
  • 6. Reply to Telegram: Ergebnis an User senden

Telegram Polling (Background-Thread)

Mit --telegram-polling wird der Telegram-Bot in einem separaten Daemon-Thread gestartet: 

telegram_mode = "polling"
def run_telegram_polling():
    telegram_app.run_polling(drop_pending_updates=True)
    
telegram_thread = threading.Thread(target=run_telegram_polling, daemon=True)
telegram_thread.start()

🔐 Security-Hinweise

Telegram User Whitelist

  • ENV-Only: User-IDs nur via TELEGRAM_ALLOWED_USER_IDS
  • Format: Komma-separierte Liste: 7664467819,123456789
  • Keine Hardcodes: IDs niemals im Code speichern
  • Unauthorized: Nicht-whitelisted User erhalten "Nicht autorisiert" Antwort

Secret-Masking

  • Automatisch maskiert: token, password, secret, key, bearer
  • Safepoints: Alle Secrets werden vor Archivierung maskiert
  • Logs: Keine Tokens in Log-Ausgaben

Port-Policy (PORTIER 3.0)

  • Erlaubter Bereich: 12344–12399
  • Verbotene Ports: 8080 (reserviert für OpenWebUI UI)
  • Enforcement: PortPolicy.is_valid_port() bei Startup
